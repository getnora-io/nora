**Docker: a tag that no upstream has is remembered for a short time, and concurrent requests for it share one round of upstream requests (#1192)** — a manifest that exists nowhere reached every upstream on every request: a CI loop over a missing image multiplied the load on the upstreams until they rate-limited NORA, and then public pulls failed as missing too. Now the first request asks the upstreams, concurrent requests for the same tag wait for that answer, and a tag that every upstream answered `not found` for is answered `404` without asking again for `[docker] miss_ttl` seconds (`NORA_DOCKER_MISS_TTL`, default `30`; `0` turns the remembering off). A miss is remembered only when every upstream asked said `not found`: an upstream that failed, refused NORA's credentials, or rate-limited it leaves the miss unremembered. A tag pushed to NORA is served at once. Referrers tags (`sha256-…`) are never remembered, so their answers during an outage are unchanged.
