**A Terraform registry module installs through NORA (#1209)** — NORA answered every module download with `X-Terraform-Get` rewritten to its own `…/source` endpoint, and neither kind of source survived that with the Terraform CLI: a `git::` source (most public modules on registry.terraform.io) was fetched from its repository address as a plain web page, which NORA served as `application/zip` and cached for a year (`error downloading …: no source URL was returned`), and an archive source lost what tells go-getter it is an archive (`XML syntax error … U+001F`). Now an HTTP source that names an archive — an extension such as `.tar.gz` or `.zip`, an `archive=` parameter, or a GitHub codeload URL — is answered as `…/source?archive=<kind>` with its `//subdir` kept, and downloaded and cached through NORA as before; what the source answers is served and cached only when it is an archive (otherwise `502`). A `git::`/`hg::` source, or an HTTP address that names no archive, is answered unchanged and Terraform fetches it itself, so the client needs access to the git host; serving git sources from NORA for air-gapped networks is #1213. A source address stored by an earlier release for a git module is no longer used: the upstream is asked again.
