**The default read rate limit fits a build host: 5000 requests a second, burst 50 000, per client (#1326)** — the read bucket introduced in #1220 (1000 a second, burst 2000) was sized for one interactive client. A Spring Boot build resolves about 1200 files at once, so a CI runner with several jobs, or builds behind one NAT address, got `429`: measured on 1.4.7, 10 and 30 concurrent `mvn package` from one address failed every time, with Maven's own retries, while with the limiter off all of them passed and NORA used under one core. The read defaults are now 5000 a second with a burst of 50 000, so tens of concurrent builds from one address pass while the limit still bounds how fast one address can send requests (it is a request rate, not a guard against every way one client can load the server). Writes (`upload_*`) and authentication (`auth_*`) are unchanged. A configured `general_rps` / `general_burst` (or `NORA_RATE_LIMIT_GENERAL_RPS` / `_BURST`) replaces the new defaults; until 1.5 a read still gets the larger of `general_*` and `upload_*`, setting by setting, as since #1205.
