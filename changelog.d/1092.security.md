**Curation and internal namespaces decide on the artifact a request resolves to (GHSA-j734-gqxg-24r5)** — a request could name an artifact otherwise than curation checked it. A path with an empty segment (`//`, a leading or trailing `/`) reached the same stored object as the path without it, past curation, internal namespaces and integrity pins; storage keys and package names now refuse empty segments, and `*` in a pattern or an OIDC scope no longer matches an empty one. Names and versions are compared in the form each registry resolves them — PEP 503 names and PEP 440 versions for PyPI, lowercase ids and normalized versions for NuGet, crates.io canonical names for Cargo, lowercase names for Terraform, `semver.clean` versions for npm, canonical versions for Go, pub_semver's form for pub — and a pattern's body takes that form in every pattern syntax, so a rule, an allowlist entry or an internal namespace holds however it spells the package or the version. File names are read as their clients read them: PyPI files as pip and setuptools do, CPAN archives as CPAN::DistnameInfo does (any extension case, `.tar.Z` included), and a RubyGems file every way RubyGems can build it, curation weighing each reading for the gem and its gemspec alike until the compact index tells which gem the file is. A Maven metadata path counts for every artifact it can belong to. Terraform module downloads and archives, a provider's files (archive, checksums, signature) and its platforms in the network mirror pass curation and namespace isolation, and an internal provider or module is answered from the cache only. For an internal name no request goes upstream, release-date lookups included.
