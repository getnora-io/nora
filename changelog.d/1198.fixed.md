**An open circuit breaker on one Maven or Docker upstream no longer stops the request (#1198)** — with `circuit_breaker.enabled = true`, an upstream whose breaker was open ended a Maven download, a Docker manifest or a Docker blob with `503`, although the next configured upstream would have served it; Maven also kept one breaker for all of `maven.proxies`, so a dead first upstream opened it for the others too. Each Maven upstream now has a breaker of its own, keyed `maven:<upstream URL>` like Docker, PyPI and npm (the `nora_circuit_breaker_state` and `nora_circuit_breaker_rejections_total` series move from `registry="maven"` to `registry="maven:<url>"`; match `registry=~"maven(:.*)?"`; `[circuit_breaker.overrides.maven]` still applies to every Maven upstream). An upstream whose breaker is open is skipped and the next one asked. When none serves, an upstream's `404` decides as before; otherwise the answer is the `503` with `Retry-After` it was, and a cached copy that could not be revalidated is served stale instead, as when the upstream fails. A Docker name bound to one upstream through `namespaces` has no next upstream and still gets `503`.
