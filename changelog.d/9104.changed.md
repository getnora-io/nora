**The password lockout counts per account, and a client is one address on a dual-stack listener** — the lockout counted wrong passwords per client address, so behind one NAT a few wrong passwords for one account locked every account out, and any login from it cleared them all. It now counts a username at an address; an address is still held for every username after ten accounts' worth of wrong passwords, which a login does not clear. Only passwords count: an API token sent as the Basic password, or over Bearer, is still verified during a lockout, and a valid credential refused with `403` is not counted. On `NORA_HOST=::` (the image default) an IPv4 peer arrived as `::ffff:a.b.c.d` and missed `trusted_proxies`, so every client behind a loopback proxy shared one lockout and one rate-limit bucket; addresses are now IPv4 wherever they are read. `X-Forwarded-For` from a peer outside `trusted_proxies` is still ignored, now with one warning naming the peer.
