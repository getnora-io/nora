**A NuGet release keeps its age when the registration is refetched (#1146)** — with `min_release_age` set and upstream dates not trusted (`NORA_TRUST_UPSTREAM_DATES=false`, the default), a NuGet version's age was the modification time of the cached registration document, and every refetch after `NORA_NUGET_METADATA_TTL` rewrote that file, on a 304 too. A release that clients asked for more often than the minimum age never matured: the download was refused with "package is 0h old". NORA now records, per package, when it first saw each version listed in a registration index or page, and the age of a version counts from that moment: a refetch, 200 or 304, keeps it, and a version a later registration lists starts at zero. The record sits in storage next to the cache, survives restarts, and is carried by `nora backup` and `nora migrate`; a registration cached before the upgrade starts the versions it lists at its last write time. Other formats that date a release by a rewritten metadata file (pub, Conan, Cargo, Terraform, PyPI) are not changed by this entry.
