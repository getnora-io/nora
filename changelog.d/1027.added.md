**Composer (PHP) registry (#1027)** — NORA hosts and proxies Composer 2 packages. It is off by default: enable it with `[composer] enabled = true` or `NORA_COMPOSER_ENABLED=true` (`NORA_REGISTRIES_ENABLE=all` includes it). With `repositories` pointing at `http://nora:4000/composer`, `composer require`, `install` and `update` fetch from Packagist, or from the upstreams in `[composer] proxies` tried in order, through NORA: package metadata is cached as the upstream sent it and served with every download URL rewritten to NORA, and an archive is fetched only from the URL the upstream's metadata lists for that version and reference, then cached with its checksum verified. Packages are published with `PUT /composer/packages/upload/{vendor}/{package}/{version}` (the zip as the body, versions immutable), and a package with any uploaded version is served only from its uploaded versions, never merged with an upstream's. `composer audit` is forwarded to the upstream's advisories API. Curation names a package by `vendor/package`: blocklist, allowlist, minimum release age, digest quarantine and internal namespaces apply. `github_token` lifts the 60 requests an hour GitHub allows an anonymous client for Packagist's archives, and `keep_source = false` keeps Composer from falling back to cloning a version whose archive curation refused. The web UI lists the packages and, per package, each version as hosted or cached. Not in this release: Composer 1, search, `nora mirror` and `nora import`, retention, VCS sources, uploading branch versions and deleting a version.
