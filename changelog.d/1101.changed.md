**mimalloc is the default global allocator (#1101)** — the `nora` binary now allocates through mimalloc (feature `mimalloc`, on by default; build `--no-default-features` for the system allocator). On the static musl build, musl's allocator takes one global lock on every allocation, which under many async workers degrades into kernel futex contention and a metastable collapse — the process burns every core while throughput falls below its own maximum. Measured on the release build: an allocation-heavy request (`tags/list`, ~63k allocations per request) at 200 rps drove the musl build to 136 rps with p99 14.4 s on all 16 cores, and a 32-worker profile collapsed at ~100 rps; with mimalloc the same load served 200 rps at p99 ~24 ms on ~4 cores and never collapsed, and light requests gained ×2.4–2.6 in peak throughput. Built with mimalloc's `no_thp` feature so idle RSS stays ~16 MB. glibc builds benefit less, since glibc's malloc already uses per-thread arenas. Fixed by @clain23.
