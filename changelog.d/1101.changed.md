**mimalloc is the global allocator (#1101)** — the `nora` binary now allocates through mimalloc instead of the C library's malloc. The release image is a static musl build, and musl's malloc takes one global lock on every allocation, so under load every tokio worker spun on that lock: on a production deployment at about 200 rps, 85% of the process's CPU was in the kernel spinlock under `futex_wait`/`futex_wake`, 10–26 cores were burned and p99 latency sat above 10 s. With mimalloc the same deployment serves 215 rps on 0.87 cores with p99 at 2.8 s and no spinlock in the profile. glibc builds benefit too, but less, since glibc's malloc already has per-thread arenas.
