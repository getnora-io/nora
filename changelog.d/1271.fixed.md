**`migrate-docker-keys` no longer writes a proxied copy under its namespace a second time (#1271)** — the migration treated a key as already namespaced only when its first segment had a dot. A copy pulled through an upstream whose namespace has none, such as `http://harbor:5000` (namespace `harbor`) or `http://localhost:5000` (`localhost`), was taken for a bare image name and copied to `docker/<namespace>/<namespace>/…`. The namespace of each Docker upstream is now read from the configuration, explicit or derived from its URL, with the same rule the proxy uses, and such copies stay where they are. Legacy keys still move under the first upstream's namespace, and a name whose first segment holds a dot is classified as before. A bare key under an upstream's namespace is kept when it has no push record, because it cannot be told apart from a copy; a repository with a push record keeps its keys. `--dry-run` reports the same decisions as the real run.
