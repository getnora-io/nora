**Docker tag list no longer shows pull-statistics files as tags (#1132)** — once a pulled image's download count had been saved, `GET /v2/<name>/tags/list` returned a phantom tag next to the real one (`{"tags":["1.0.0","1.0.0.stats"]}`), because the tag listing skipped `.meta.json` files but not the `.stats.json` file that holds the pull count. Every place that lists Docker tags (the tags API, delete by digest, retention, the web UI and the repository index) now asks one check: a file under `manifests/` is a tag only if its name is a valid tag and it is not a metadata or statistics file. Pull counts are still read from the statistics file as before; tags such as `a.meta.b`, which were hidden by the old filter, are now listed, and a `sha512:` digest copy is no longer counted as a version in the UI.
