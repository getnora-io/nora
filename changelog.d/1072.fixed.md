**A local-storage path that is a directory is no longer served as a file (#1072)** — on the local backend a key whose path is a directory (`raw/dir` while `raw/dir/f.txt` is stored, or a directory left empty by deletes) was opened as a file: `HEAD` answered 200 with the directory's size, `GET` broke off after the headers, `DELETE` answered 500; a path below a stored file answered 500 too. Such keys now answer as missing ones, as on S3. A raw `PUT` the local store cannot hold because the name is taken answers 409 instead of 500.
