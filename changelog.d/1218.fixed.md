**Docker `tags/list` lists the tags of the upstream a name routes to (#1218)** — `GET /v2/<name>/tags/list` read only NORA's own storage, so for a name that is proxied (Docker Hub, or a `[[docker.upstreams]]` entry) it listed only the tags already copied, and a client that resolves versions through this endpoint, such as Renovate's Docker datasource, saw only those. The listing now merges the upstream's tags with the local ones, in ASCIIbetical order, the way `manifests/<tag>` resolves them, and reads every page the upstream sends. It honours `n` and `last`, and sends a `Link` header with `rel="next"` when more tags follow. Curation refuses a name it blocks before any upstream is asked, an internal namespace is never sent upstream, and a name no upstream serves is answered from local storage only. When an upstream fails, a listing with local tags is served as stale (`X-Nora-Stale: true`) if `serve_stale` is on, as a stale manifest is; otherwise, and when there are no tags to serve, the answer is `502` with an `UNAVAILABLE` body, never an empty list.
