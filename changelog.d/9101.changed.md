**An OIDC provider without `audience` stops the start** *(Action may be needed)* — a provider in `[[auth.oidc.providers]]` without `audience` used to start without a warning and accept a token whatever its `aud` (see Security). NORA now refuses to start with it, with an error naming the provider and exit status 78, which the packaged systemd units do not restart into, and refuses a SIGHUP reload that brings one in. Before upgrading, give every enabled provider the `audience` its CI jobs request (`core.getIDToken('nora')`, GitLab `id_tokens: … aud:`), or set `any_audience = true` where no nameable `aud` exists: it accepts any `aud` and warns at every start. A rollback to 1.4.2 with `any_audience` in the file warns about an unknown key, or does not start under `NORA_CONFIG_STRICT=true`.
