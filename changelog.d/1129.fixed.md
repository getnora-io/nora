A scheduled GC or retention pass that takes files out of the store (orphans, metadata phantoms, files evicted by `[gc] proxy_cache_max_bytes`, retention keys) marks the repository indexes stale, so the dashboard and `/api/ui/stats` count what is on disk right after the pass. They used to count the deleted files until a restart or the next write to that registry. `nora_artifacts_total` and `nora_storage_bytes` are read from the same index and follow at the next read of the dashboard or the stats, as after a write. A dry run changes nothing.
