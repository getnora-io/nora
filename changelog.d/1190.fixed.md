**`systemctl reload nora` works with the shipped units (#1190)** — the deployment guide says `systemctl reload nora` re-reads the configuration, but the unit in the `.deb`/`.rpm` packages, `deploy/nora.service` and the one `install.sh` writes had no `ExecReload`, so systemd refused the job (`Job type reload is not applicable for unit nora.service`) and the only way to apply a new curation policy without a restart was `kill -HUP` by hand. The three units now send the same SIGHUP (`ExecReload=/bin/kill -HUP $MAINPID`); the process keeps running and its PID is unchanged. After upgrading the package, `systemctl daemon-reload` picks up the new unit (the package scripts do it); a unit installed by `install.sh` is updated by running it again.
