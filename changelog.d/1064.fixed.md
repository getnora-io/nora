**An npm packument the upstream confirms is no longer written again on object storage (#1064)** — when a cached packument's TTL had expired and the upstream answered `304 Not Modified`, NORA read the whole packument from storage twice and wrote it back, only to move the body's modification time, which the freshness check read. On object storage every such revalidation downloaded and re-uploaded the body. A 304 now reads the body once and writes only the small validator sidecar, which records when the upstream last confirmed the copy, and freshness is read from there. A copy without such a record keeps the body's write time as before, and an upstream that stops sending validators leaves no stale record behind. The release age that curation falls back to for a version the first-seen ledger does not list is read as before. The responses are byte-for-byte the same.
