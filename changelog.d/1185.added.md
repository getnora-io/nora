**`nora mirror go` fills the Go module proxy for an offline `go mod download` (#1185)** — `nora mirror` had no Go subcommand: `nora mirror go` exited with `unrecognized subcommand 'go'`, and Go modules could only be seeded by running the go command through NORA once. `nora mirror go --modfile go.mod` now reads the requirements of go.mod and the go.sum beside it (or the one given with `--sumfile`) and fetches each module version through NORA's `/go/` proxy, so NORA stores it under the key it serves and curation judges it as it judges a go client. A required module gets its `.info`, `.mod` and `.zip`, after the `replace` directives: a module replaced by another is fetched as the replacement, and a module replaced by a directory is skipped. A version that go.sum lists with a module hash gets the same three files, and a version listed only with a `/go.mod` hash gets its `.mod`, which the go command reads to build the module graph — unless go.mod's `go` line is older than 1.17 or missing: then `go mod download` downloads every module of the graph, and every go.sum version gets all three files. A directory replacement may be quoted, a space included (`=> "../local module"`). A requirement on a branch, tag or commit (`vnext`, `master`) is resolved through its `.info`, and the files of the version it names are fetched, as the go command fetches them; a query the go command resolves from the version list (`latest`, `v1`, `v1.2`) stops the command with its line and a hint to run `go mod tidy`. Paths and versions are escaped as the go command escapes them (`github.com/BurntSushi` is asked as `github.com/!burnt!sushi`). A file NORA cannot serve fails its module version, and the command exits non-zero. A go.mod or go.sum line that cannot be read stops the command with its file and line number, before anything is fetched. Measured with go 1.22.5 against a store filled only by `nora mirror go`, with the upstream and every other host unreachable: `go mod download`, `go build`, `go mod verify` and `go list -deps -test all` of a project with 10 requirements and 26 go.sum lines succeed; with go 1.22.5 and 1.26.3, `go mod download`, `go build` and `go mod verify` succeed for a `go 1.16` project whose go.sum lists a dependency only with its `/go.mod` hash, for a go.mod without a `go` line, for a quoted directory replacement with a space, and for requirements on `vnext` and `master`. On 1.4.5 the command does not exist.
