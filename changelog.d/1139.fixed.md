**npm retention keeps the surviving versions of a proxied package installable (#1139)** — a `keep_last` or `older_than_days` rule that removed a cached tarball of a proxied package rebuilt its packument from the per-version documents that only published packages have, so the packument came back with `versions: {}`; with the upstream unreachable, `npm install` of the version retention kept failed with `ENOVERSIONS`. Retention now edits the cached upstream packument instead: the versions it removed are dropped, every other version keeps its upstream document (`dist.tarball`, `shasum`, `integrity`), a dist-tag pointing at a removed version is dropped and `latest` is re-pointed at the highest version left, and the stored upstream validators are cleared so the next revalidation fetches the full document. A package with published versions is regenerated from them as before, including when it also has tarballs cached from the upstream.
