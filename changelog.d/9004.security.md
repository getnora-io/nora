**A storage read error produced wrong but successful answers (GHSA-XXXX-XXXX-XXXX)** — when NORA could not read its own copy of a package's metadata or integrity data (an error, not a missing key), it could answer with a PyPI index link without its `#sha256=`, an npm version, tag or field left out, `403` for an internal package or `404` for one that exists — a client could install without verification or resolve an internal name elsewhere. These cases now answer `503` (`500` on an integrity violation), the upstream is not asked and no digest is left out, across npm, PyPI, NuGet, Terraform, CPAN, Conan, RubyGems and the other formats.
