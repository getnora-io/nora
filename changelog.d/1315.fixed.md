**Composer answers If-Modified-Since by date (#1315)** — the metadata endpoints compared `If-Modified-Since` with the `Last-Modified` they would send as a string, so only a client that returned the exact bytes got a `304`: the same date in RFC 850 or asctime form, or a later date (a cache that stores when it fetched), got the full document. The value is now parsed as an HTTP-date in all three forms (RFC 9110) and compared as a date; a value that is not one valid date, or is later than the server's clock, is ignored, and `If-None-Match` still decides alone. Composer itself sends back the value it was given and is not affected.
