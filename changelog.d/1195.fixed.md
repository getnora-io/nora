**A Docker image name behind a registry host no upstream serves is no longer answered by another registry (#1195)** — `nora.example/quay.io/project1/service1` with only Docker Hub configured was stripped to `project1/service1` and asked of the fallback chain, so whoever registered that name on Docker Hub decided what a client asking for quay.io received, and a cached Docker Hub copy was served under the quay.io name. Such a name is now asked of no upstream: it is answered from NORA's storage only (an image pushed to NORA under that host is still served) and is otherwise `404`; under `default_action = "deny"` it is refused as before. A host names an upstream by its storage namespace or by the host of its `url`, so `registry.gitlab.com/…` reaches an upstream at `https://registry.gitlab.com`, whose namespace is `gitlab.com`. `docker.io`, `index.docker.io` and `registry-1.docker.io` all name Docker Hub; without a Docker Hub upstream they go to the fallback chain as before. To proxy another registry by its host, add it as an upstream.
