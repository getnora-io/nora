**`npm search` works through NORA (#1148)** — NORA forwarded the path of an npm registry endpoint such as `/-/v1/search` but not its query string, so the upstream got a search with no `text` (registry.npmjs.org: `400 'text' query parameter is required`) and `npm search` failed with `E404 'search' is not in this registry`. The query now reaches the upstream as the client sent it. Under a namespace filter (`curation.internal_namespaces`) or with scopes owned by a private upstream (`npm.proxies` `scopes`), a search that names an internal package or such a scope — `@internal/x`, `scope:vendor`, `corp-billing` matching `corp-*` — is refused with `422` and the reason, and is not sent upstream, as an `npm audit` carrying such names already is; npm prints the reason.
