**A `[[docker.upstreams]]` entry with an unknown key, or a `prefix` with `*` or `?`, refuses to start (#1188)** — an unknown key in an upstream entry used to be listed in the startup warning and ignored, so a misspelt `namespaces` would have left a private registry in the fallback chain. A `prefix` is matched literally, so `prefix = "*"` matched no name; under `default_action = "deny"` it refused every image that no other `prefix` routed. Both are now startup errors that name the entry. Copies of public names are stored under the first upstream without `namespaces`, which is the first upstream for every configuration that does not use them. The `403 DENIED` refusal under `default_action = "deny"` now says that no `prefix`, `namespaces` or registry host routes the name; it named only `prefix`.
