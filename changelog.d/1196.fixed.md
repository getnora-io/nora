**A Docker upstream that refuses NORA's credentials is a `502` that says so (#1196)** — an upstream that answered `401` with a challenge NORA cannot answer with a token (Harbor's `Basic realm="harbor"` for a robot account without access to the project), or whose token server refused the credentials with `401` or `403` (Docker Hub's "incorrect username or password"), was logged as "every upstream failed" and answered with an empty `502`, as an outage would be. Both are now logged at `warn` with the upstream's URL, as "upstream refused NORA's credentials" or, with no credentials configured for it, "upstream requires credentials and none are configured for it", and answered with `502` and an OCI `DENIED` body that names the refused credentials. As before, such a refusal does not count toward opening the circuit breaker, and in the fallback chain another upstream's answer still decides. A `401` that persists after the token server issued a token stays a `404`: Docker Hub answers a repository that does not exist that way, so it cannot be told from a refusal.
