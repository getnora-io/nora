**Maven retention stops advertising the versions it deletes (#1281)** — a retention rule deleted a Maven version's files but left the artifact's `maven-metadata.xml` as it was, so the document went on listing the deleted version, and `<latest>` or `<release>` could still name it. A client resolving `RELEASE`, `LATEST` or a version range picked that version and got a 404. Retention now removes the versions it deleted from the stored document, points `<latest>` and `<release>` at the highest version left, rewrites the document's checksums, and deletes the document when no version is left. Versions a hosted+proxy read merged in from an upstream (#885) stay listed. A retired SNAPSHOT's own `maven-metadata.xml` and checksums are deleted with it: left behind, they kept the version directory alive and the next deploy listed the version again. A dry run changes nothing.
