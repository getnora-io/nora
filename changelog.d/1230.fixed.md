**`terraform init` works on a warm cache while the Terraform upstream does not answer (#1230)** — with an upstream that accepts the connection and never answers, every Terraform metadata request waited for `NORA_TF_PROXY_TIMEOUT` twice before the stored copy was served (the failed request was retried once first): about 61 s with the default 30 s, while Terraform gives up on a mirror request after 10 s and tries twice, so `terraform init` failed although every provider it needed was cached. The network mirror `index.json` and `{version}.json` also came back unmarked, with `Cache-Control: public, max-age=60`, nothing was logged, and with the circuit breaker on, an open breaker answered `503` instead of the stored copy. Now, when a stored copy is there to serve stale, the upstream is asked once, for at most the new `revalidate_timeout` (`NORA_TF_REVALIDATE_TIMEOUT`, default 5 s, never longer than `proxy_timeout`), and an open breaker serves the copy at once. With `trust_upstream_dates` on, the release-date query to registry.terraform.io shares that time with the revalidation, so download metadata and the mirror `{version}.json` also come within it. Every such answer, on the mirror paths and on the provider version list, download metadata and module version list alike, carries `X-Nora-Stale: true` and `Cache-Control: public, max-age=0, must-revalidate`, is logged as a warning and is counted in the new `nora_proxy_stale_served_total{registry}` metric; a request the stale version list answers with a `404` or `502` is neither logged nor counted. A stored copy that is not JSON is never served and does not cost the request its retry, and a version list the upstream answers with something that is not JSON is not stored: the stored copy is served stale instead. Measured with Terraform 1.9.8 against an upstream that never answers and default settings: `terraform init` now completes in about 11 s from the cache, where 1.4.5 fails after 21 s. With no stored copy nothing changes: the full `proxy_timeout`, one retry, then `502` (`503` with the breaker open). A copy within `metadata_ttl` and a stored provider archive are still served without asking the upstream, and an upstream that answers still refreshes the copy. `revalidate_timeout = 0` is refused at startup, since a stored copy would then never be refreshed.
