**Terraform serves a stored copy within one upstream timeout when the upstream does not answer, and marks it stale (#1230)** — with an upstream that accepts the connection and never answers, every Terraform metadata request waited for the proxy timeout twice (the request was retried once before falling back to the stored copy), about 61 s with the default `NORA_TF_PROXY_TIMEOUT=30`, longer than Terraform waits for a mirror, so `terraform init` failed with a warm cache. The network mirror `index.json` and `{version}.json` also came back unmarked, with `Cache-Control: public, max-age=60`, and nothing was logged. When a stored copy is there to fall back to and `serve_stale` is on, the upstream is now asked once, so the copy comes within one timeout. Every such answer, on the mirror paths and the provider version list, download metadata and module version list alike, carries `X-Nora-Stale: true` and `Cache-Control: public, max-age=0, must-revalidate`, is logged as a warning and counted in the new `nora_proxy_stale_served_total{registry}` metric. With no stored copy the request is still retried once before the `502`, a copy within `metadata_ttl` is still served without asking the upstream, and a stored provider archive is still served without waiting for it. Terraform waits 10 s for each mirror request (measured with Terraform 1.9.8), so with the default `NORA_TF_PROXY_TIMEOUT=30` the copy still comes too late for `terraform init`: where the upstream may not answer, set it below 10 s.
