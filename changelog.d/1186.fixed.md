**`[tls] ca_cert` now covers the S3 and GCS storage client (#1186)** — the CA bundle named by `[tls] ca_cert` (`NORA_TLS_CA_CERT`) was trusted only by the clients for upstream registries and import. An S3-compatible store with a certificate from a private CA (MinIO, Ceph RGW, an on-prem gateway) was refused at the handshake, so `/ready` stayed 503 and every write failed with a log that said nothing about the certificate. The object store client now trusts every certificate in the bundle as well, on top of the system trust store, which stays in use; `nora migrate` builds both ends the same way. A bundle that cannot be read or holds no usable certificate stops a start on S3 or GCS with exit code 78 and the bundle's path. Deployments on local storage do not read the bundle for storage.
