**Hugging Face Hub pull-through proxy (#579)** — opt-in with `NORA_HF_ENABLED=true` (`[hf] enabled = true`); `NORA_REGISTRIES_ENABLE=all` leaves it off. With `HF_ENDPOINT=http://nora:4000/hf`, `hf download`, `hf_hub_download` and `snapshot_download` fetch public models through NORA: model info, revisions and tree listings on every request, and files through the Hub's redirects, which NORA follows itself so no client request leaves for the Hub or its CDN. Files are cached per repository by the digest the Hub names them by (the sha256 of an LFS file, the git blob sha1 of a regular one): every file is checked against that digest on the way in, with its last chunk held back until it matches, and a weight file that does not change across commits is downloaded once. The Hub's answer that names the commit is asked on every download, so `main` never goes stale. Xet is never proxied or advertised: `xetHash` is removed from metadata and Xet headers and links never reach the client, so downloads stay on plain HTTP. Curation names a download by its repository id and its commit, and an alias (`gpt2`) by its canonical id too (`openai-community/gpt2`); `curation.min_release_age` with hf enabled is refused at start. Cached files count toward `[gc] proxy_cache_max_bytes`, and retention rules that name `hf` prune them (a `*` rule does not). Measured with huggingface_hub 0.36.0, 1.0.0, 1.33.0, 2.0.0, 2.1.1 and 2.2.0. Not in this release: datasets (501), private and gated repositories (a client's token is never sent upstream), uploads, and serving while the Hub is unreachable.
