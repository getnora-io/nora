**NORA's own date code moves off `chrono` (#1282)** — `chrono` is marked unmaintained (RUSTSEC-2026-0543). Every date NORA writes or reads now goes through one module on the `time` crate, which was already in the dependency tree, so the build pulls in no new crate. Nothing changes on the wire or in storage: the audit log, activity feed, backup metadata, Docker token `issued_at`, `Last-Modified` of raw files and Composer documents, apt `Release` dates, Maven `lastUpdated` and Composer upload times are written byte for byte as before, and upstream dates (npm `time`, PyPI, NuGet `published`, Go, Cargo, Conan, Pub, Ansible, Terraform, RubyGems, Composer) and stored backup metadata are read with the same leniency, including RFC 3339 with a space or lower-case `t`, offsets without a colon, leap seconds and fractions longer than nine digits. Golden tests pin each spelling, and a corpus of 5273 date strings pins what the parsers made of them before the change. `nora-registry` no longer depends on `chrono` itself; it stays in the tree only through `object_store`, and `deny.toml` keeps the advisory accepted for that reason.
