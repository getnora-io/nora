**`/health` answers 503 when the server can only be fixed by a restart** *(Action may be needed)* — a request handler that panics now answers `500` and the server keeps serving (see Security), and every long-lived background task runs under a supervisor that logs `background task panicked`, counts it in `nora_task_panics_total{task}` and restarts the task after a backoff. `/health` answers `503` with `failing_task` when a task keeps panicking, or when the maintenance loop has finished no tick for `server.maintenance_stall_secs` (300 s); a tick waiting on a storage that does not answer is cut and fails `/ready`, not `/health`. A panic of the audit writer ends the process with exit status 70. Kubernetes restarts on the liveness probe; under Docker without Swarm, or systemd, a `503` restarts nothing by itself — add an autoheal watcher or a timer running `nora healthcheck || systemctl restart nora`.
