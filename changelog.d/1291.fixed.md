**Maven retention no longer leaves a retired SNAPSHOT listed in two corner cases (#1291)** — the fix for #1281 left two cases as they were in 1.4.5. A proxy fetch of a SNAPSHOT's version-level `maven-metadata.xml` that ran while retention removed that document could leave the document's checksums behind without the document. And an artifact whose id looks like a version of another artifact, such as `com.example.lib:1.0-SNAPSHOT` next to `com.example:lib`, kept the other artifact's version listed: after retention removed `com.example:lib:1.0-SNAPSHOT`, its `maven-metadata.xml` still listed the SNAPSHOT, and `<latest>` could name it, because the files under `com/example/lib/1.0-SNAPSHOT/2.0/` were counted as files of that version. The proxy fetch now writes a version-level document and its checksums under the artifact's lock, the lock retention takes to remove it. Whether a version is stored is now decided by that version's own files: each Maven key is read once into group, artifact, version and file name, and a key of another artifact or a `maven-metadata.xml` in the version directory no longer counts.
