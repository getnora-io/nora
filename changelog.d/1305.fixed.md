**A request for a cached npm packument holds far less memory (#1305)** — one request for a cached packument held about ten times the document when the client asked for the abbreviated form (`Accept: application/vnd.npm.install-v1+json`, what pnpm sends), because the whole document was built as a tree in memory and the kept fields were copied out of it: ten parallel `pnpm install` runs of a package with a 16 MB packument, such as typescript, took NORA past 1.8 GiB. The abbreviated form is now read from the document in one pass, one version at a time, and the request holds at most about two and a half times the document. A request for the full document now holds it once: the local store reads a file into a buffer of its size rather than one grown by doubling, the record NORA keeps at the head of a cached copy is cut off without copying the document, and the tarball links of a copy are checked once per request rather than twice. The bytes a client gets are unchanged, and so are the storage round-trips of a request. The number of requests in flight is still not limited, so the memory still grows with them.
