**NuGet search and autocomplete send a host only the protocol's own parameters, each internal-namespace term checked (#1329)** — `autocomplete` checked `id` against `curation.internal_namespaces` when the request had one and `q` otherwise, and both endpoints forwarded the client's whole query string, so `/nuget/v3/autocomplete?id=public.pkg&q=corp.lib` with `internal_namespaces = ["corp*"]` sent `corp.lib` to the public autocomplete service, and so did any parameter a client added (`?q=public&extra=corp.lib`). The query a host gets is now rebuilt from the parameters the NuGet search and autocomplete protocols define — `q`, `id` (autocomplete), `skip`, `take`, `prerelease`, `semVerLevel`, `packageType` — plus the `framework` filter some hosts take; anything else stays in NORA. When `q`, `id`, `packageType` or `framework` names an internal namespace the answer is built locally with no upstream request, and an empty term matches no pattern. The dotnet client sends only these parameters, so restore and search behave as before. An internal name written inside `q` with NuGet's field syntax (`packageid:corp.lib`) is tracked in #1330.
