**A per-registry `min_release_age` applies without a global one (#1098)** — the minimum-release-age filter was built only when `curation.min_release_age` was set, so `[curation.npm] min_release_age = "3d"` (or `NORA_CURATION_<REGISTRY>_MIN_RELEASE_AGE` for npm) on its own was dropped without a word: enforce mode refused to start with "no active control is configured", and with any other control NORA started and served packages younger than the configured age. The filter is now built when the global value or any per-registry value is set; the global value is the default for registries without their own, and a registry's own value wins in its registry. At startup a per-registry value is an active control in enforce mode when it applies; on an enabled proxy registry it needs a quarantine of that registry — `curation.<registry>.quarantine` or the global `curation.quarantine` — since a quarantine on another registry holds none of its downloads. A value that could never apply is refused naming its key: rpm and deb downloads are not checked by name or release date, and cpan downloads carry no release date. A value on a disabled registry is reported as unused and is not counted as a control. Every startup rule on `min_release_age` — this one, the global one (#741) and the Hugging Face one — now judges the registries the server mounts, however they are enabled (`NORA_REGISTRIES_ENABLE`, `[registries].enable` or a registry's own flag): before, they read the per-registry flags before the enable-set was applied, so a registry left out of the set was judged as enabled and one added by it as disabled, and `NORA_REGISTRIES_ENABLE=all,hf` with a global `min_release_age` started. `NORA_HF_ENABLED`, `NORA_RPM_ENABLED`, `NORA_DEB_ENABLED` and `NORA_CPAN_ENABLED` beside an enable-set are now warned about like the other per-registry flags. Configurations that start on 1.3.6 and stop on this release, each naming the key: a `min_release_age` for rpm, deb or cpan; a per-registry value on an enabled proxy registry without a quarantine of that registry (1.3.6 ignored such a value without a global one, and beside a global one accepted a quarantine on any registry); a global `min_release_age` without a quarantine while an enable-set mounts proxy registries whose own flags are off (`NORA_REGISTRIES_ENABLE=all` with `[npm] enabled = false` and the like); and a global one with Hugging Face mounted by `all,hf`. One starts that 1.3.6 refused: a global value with only hosted registries mounted, raw among them, whose uploads it holds by their own date. With only a global value, `curation explain` and the startup log read as before. Hugging Face has no curation section of its own, so a setting for it — `[curation.hf]` in the config file, or `NORA_CURATION_HF_MIN_RELEASE_AGE`, `NORA_CURATION_HF_QUARANTINE` or `NORA_CURATION_HF_QUARANTINE_TTL` — stops startup with the reason instead of being ignored; Hugging Face models are held by repository id and commit in the allowlist and blocklist.
