**A per-registry `min_release_age` applies without a global one (#1098)** — the minimum-release-age filter was built only when `curation.min_release_age` was set, so `[curation.npm] min_release_age = "3d"` (or `NORA_CURATION_NPM_MIN_RELEASE_AGE`) on its own was dropped without a word: enforce mode refused to start with "no active control is configured", and with any other control NORA started and served packages younger than the configured age. The filter is now built when the global value or any per-registry value is set, the global value being the default for registries without their own; cpan's value, which a hand-written list of sections had left out, applies too. The startup rules cover a per-registry value too: in enforce mode it is an active control, and on an enabled proxy registry it needs a quarantine of that registry — `curation.<registry>.quarantine` or the global `curation.quarantine` — since a quarantine on another registry holds none of its downloads; a 1.3.6 configuration that set a per-registry value beside a global one, with a quarantine only on another registry, now stops at startup naming the key. A value for rpm or deb, whose downloads are not checked by name or release date, is refused at startup instead of being accepted and never applied, and in enforce mode an unparsable per-registry value stops startup as an unparsable global one does.
