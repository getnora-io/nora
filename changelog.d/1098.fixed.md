**A per-registry `min_release_age` applies without a global one (#1098)** — the minimum-release-age filter was built only when `curation.min_release_age` was set, so `[curation.npm] min_release_age = "3d"` (or `NORA_CURATION_NPM_MIN_RELEASE_AGE`) on its own was dropped without a word: enforce mode refused to start with "no active control is configured", and with any other control NORA started and served packages younger than the configured age. The filter is now built when the global value or any per-registry value is set; the global value is the default for registries without their own, and a registry's own value wins in its registry. At startup a per-registry value is an active control in enforce mode when it applies; on an enabled proxy registry it needs a quarantine of that registry — `curation.<registry>.quarantine` or the global `curation.quarantine` — since a quarantine on another registry holds none of its downloads. A value that could never apply is refused naming its key: rpm and deb downloads are not checked by name or release date, and cpan downloads carry no release date. A value on a disabled registry is reported as unused and is not counted as a control. Configurations that start on 1.3.6 and stop on this release, each naming the key: a `min_release_age` for rpm, deb or cpan, and a per-registry value on an enabled proxy registry without a quarantine of that registry (1.3.6 ignored such a value without a global one, and beside a global one accepted a quarantine on any registry). With only a global value, `curation explain` and the startup log read as before.
