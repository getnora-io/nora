**An API token works as the Basic password without htpasswd (#1094)** — with auth enabled and no htpasswd file, the OIDC-only setup from #996, every Basic request was refused with `401 Basic auth not configured` before API tokens were checked, so `docker login`, twine and Maven could not use an `nra_` token that Bearer accepted. The Basic path now checks htpasswd when there is one and then the token store, with the same role gates (a read token gets 403 on writes, `/api/v1/admin/*` needs an admin token), 503 on a token-store failure and 401 counted toward the lockout for a wrong token. With htpasswd configured nothing changes. The OIDC-only startup line now reads `No htpasswd (OIDC-only): Basic auth accepts API tokens only` instead of `Basic auth disabled (no htpasswd); OIDC is the write path`.
