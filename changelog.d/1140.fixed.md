**npm release age no longer restarts at every packument refetch (#1140)** — with `min_release_age` set and upstream dates not trusted (`NORA_TRUST_UPSTREAM_DATES=false`, the default), an npm version's age was the modification time of the cached packument, and every refetch after `NORA_NPM_METADATA_TTL` (300 s by default) rewrote that file — on a 304 too. A package that clients asked for more often than the minimum age never matured: `npm install` was refused with "package is 0h old" indefinitely. NORA now records, per package, when it first saw each version listed in an upstream packument, and the age of a version counts from that moment: a refetch, 200 or 304, keeps it, and a version the upstream adds later starts at zero. The record sits in storage next to the cache (local and S3 alike), survives restarts, and is carried by `nora backup` and `nora migrate`; a packument cached before the upgrade starts the versions it lists at its last write time. A version no fetched packument has listed is judged as before, and the quarantine first-seen clock and trusted upstream dates are unchanged.
