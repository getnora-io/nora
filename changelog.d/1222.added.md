**Docker `metadata_ttl` can be set per upstream (#1222)** — one `[docker] metadata_ttl` window applied to every proxied tag, so an operator either revalidated every tag of every upstream, with the extra round trips and rate-limit pressure that brings, or served a re-pushed upstream tag stale. A `[[docker.upstreams]]` entry can now set its own `metadata_ttl`, in the same values: a positive number of seconds serves a tag copy from cache for that long, and a value that is not positive revalidates every pull. A copy takes the window of the upstream whose storage namespace it is stored under. An upstream without the key follows the global value, so a config without it behaves as before. A copy from the fallback chain (an upstream without `prefix` or `namespaces`) is stored under the first upstream's namespace, and takes that upstream's window.
