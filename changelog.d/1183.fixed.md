**`nora mirror pip` and `nora mirror cargo` fill a store that an offline client installs from (#1183)** — `nora mirror pip` fetched only the project page `/simple/<name>/` of each requirement, and `nora mirror cargo` only the `.crate` files. Both still reported every package as mirrored. In an isolated network, `pip install` against the store found no version (`from versions: none`) and `cargo fetch` got `502` for every sparse index entry. Now `nora mirror pip` fetches every file of the pinned version of each requirement: each wheel and the sdist, because the platform and Python version of the client that installs later are not known. `nora mirror cargo` fetches the sparse index entry of every locked crate as well as its `.crate`. A requirement that is not pinned to one version (`>=`, `~=`, a wildcard or no version) names no files, so it is reported as failed and the command exits non-zero. A requirement whose files NORA cannot serve, or a crate whose index entry is missing or does not list the locked version, is reported the same way. Requirements files written by `pip-compile --generate-hashes` are now read correctly: before, continuation lines, `--hash` options, extras and environment markers were read as package names and versions. Measured with pip 22.0.2 and cargo 1.96.0 against a store filled only by `nora mirror`, with every upstream unreachable: `pip install` of `requests` 2.32.3 and its four dependencies, and `cargo fetch --locked` of five crates, now succeed. On 1.4.5 both fail.
