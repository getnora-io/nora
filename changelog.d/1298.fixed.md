**Retention no longer deletes a package that an upload of the same path is writing (#1298)** — an RPM upload stores the package and then its metadata under the repository's lock, while retention deleted each file of a version under that file's own lock, from a plan made earlier. A package uploaded again at a path retention was deleting could be stored, deleted, and the upload still answered `201`: the package was gone and the repodata rebuilt afterwards did not list it. Debian uploads, Maven deploys and PyPI uploads had the same gap (a redeployed file left without its checksums, an uploaded file left unrecorded and unlisted). Retention now deletes a version of these formats under the lock its uploads hold, and only if the version is still the one it planned from: the same files, as old as they were. A version that changed in between, or was still being uploaded when the plan was made, is kept, is not counted as deleted, and is judged again on the next pass. A Maven checksum a client uploads is stored under the same lock as the file it belongs to.
