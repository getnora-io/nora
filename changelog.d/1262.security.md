**Upstream credentials written in an address stay out of every output (#1262)** — Upstream credentials written in the address (`https://user:secret@host`) no longer reach `/metrics`, a 503 or 429 body, the log or the quarantine journal when the address is spelled `https:///user:secret@host`, `https:/user:secret@host`, `https:user:secret@host` or with backslashes. The proxy client accepts these spellings and sends the credentials, but the circuit breaker key and the log filter missed them, and the breaker key is a `/metrics` label that is readable without signing in by default. Every output now reads the address with the proxy client's parser. A password with a space, a quote or angle brackets, and an address written without a scheme, are masked too, and an upstream address refused at startup is no longer printed with its credentials.

Docker: an upstream configured with credentials in its address and no `namespace` stored its proxy cache under the user name (`docker/<user>/…`), which the Docker list shows. The namespace is now the host. After the upgrade, images cached before are fetched from the upstream again into `docker/<host>/…`; offline, they are not served from the old place. The old directory stays in storage, and the Docker list keeps showing its name, the user, until it is removed: after upgrading, delete `docker/<user>/` from storage. It holds that upstream's proxy cache, which is fetched again on the next pull; before deleting it, check that no image was pushed to NORA under a name starting with `<user>/`, since such an image is stored in the same directory. To keep that cache instead, either set `namespace = "<user>"` on that upstream before upgrading, which keeps the user in the storage keys and in the list, or move `docker/<user>/` to `docker/<host>/` in storage.

A configuration file that cannot be read is now reported by its path, line and column and the parser's message, without quoting the line, which could hold the password of an upstream address; a value the message quotes is masked. The same applies to a reload on SIGHUP and to a skipped `config.toml` in the working directory.
