**Docker pull counts no longer trip a false integrity alarm (#1114)** — a Docker manifest pull rewrote the manifest's `.meta.json` on every request to bump its download count, racing the integrity-pin read a concurrent pull performs; a reader that caught the file mid-rewrite saw bytes that no longer matched the pin, and the integrity gate logged `INTEGRITY VIOLATION` on healthy data nobody had tampered with — about 21 per 100 concurrent pulls of one manifest on the local backend, clients still receiving 200. Pulls now record counts in memory and flush them in batches to a separate `.stats.json` sidecar, so `.meta.json` is immutable after publish and the request path no longer writes it. S3/GCS carry the pin in object metadata and were not affected.
