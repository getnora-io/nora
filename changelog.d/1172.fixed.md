**UI pages no longer stat each stored file (#1172)** — the Go namespace pages and a Go module's versions page, and the npm, Cargo, PyPI, Conan, Pub, Ansible, Terraform and Raw package pages, listed storage and then read each listed file's size and time with a separate `stat()`, one after another. On S3 that is a HEAD request per stored version on every visit, so the pages slowed down as the cache grew. They now take size and time from the listing itself, which already carries them: a page costs the same number of storage requests whether a package has 3 versions or 40, and shows the same sizes and times as before. Measured on an S3 test server with one Go module of 200 cached versions: `/ui/go` went from 602 HEAD requests and about 3.3 s a visit to none and 0.3 s, the module page from 201 and 1.5 s to none and 0.5 s. On S3, a Go module version or a scoped npm tarball written by NORA 0.9.2 or earlier (before #534 changed how `@` is written in object keys) still shows as cached with its own size and time: where the prefix holds an `@`, these two pages also list its old form, one more request a visit. If a listing fails, they read each version's metadata as before instead of showing stored versions as not cached, and log a warning.
