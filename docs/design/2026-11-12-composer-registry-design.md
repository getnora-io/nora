# Composer Registry — Design

## Overview

Composer (PHP) support for NORA (#1027): packages uploaded to NORA, and a
pull-through cache of Composer 2 repositories — Packagist by default — for the
`composer` client. One repository URL serves both.

## Registry Identity

- **RegistryType:** `Composer` → `"composer"`, mount point `/composer/`, display `"Composer"`
- **Storage prefix:** `composer/`
- **Default upstream:** `https://repo.packagist.org`
- **Default state:** disabled (ADR-7); included in `all`
- **Type:** hosted + proxy, like npm, PyPI and Maven
- **Protocol:** Composer 2 (`metadata-url`, `p2/`). Packagist shut down Composer 1
  on 2025-09-01; the `providers` API is not served.

## Configuration

`config/registry/composer.rs`:

```rust
pub struct ComposerConfig {
    pub enabled: bool,                       // false
    pub proxy: Option<String>,               // Some("https://repo.packagist.org")
    pub proxy_auth: Option<ProtectedString>, // user:pass, HTTP Basic
    pub proxies: Vec<ComposerProxyEntry>,    // ordered; overrides `proxy`
    pub proxy_timeout: u64,                  // 30
    pub metadata_ttl: i64,                   // 300
    pub serve_stale: bool,                   // true
    pub revalidate: bool,                    // true
    pub github_token: Option<ProtectedString>,
    pub keep_source: bool,                   // true
}
```

Env: `NORA_COMPOSER_{ENABLED,PROXY,PROXY_AUTH,PROXIES,PROXY_TIMEOUT,METADATA_TTL,SERVE_STALE,REVALIDATE,GITHUB_TOKEN,KEEP_SOURCE}`;
curation `[curation.composer]` / `NORA_CURATION_COMPOSER_*`.

`proxy` + `proxies` follow PyPI and npm: `proxies` (URL strings or `{ url, auth }`
tables) wins when non-empty; the first upstream that has a package serves all of
its metadata, as Composer asks its own repositories in order. Every upstream has
its own circuit breaker (`composer:<url>`).

## API

| Route | |
|---|---|
| `GET /composer/packages.json` | Repository root, generated by NORA |
| `GET /composer/p2/{vendor}/{package}.json` | Tagged versions |
| `GET /composer/p2/{vendor}/{package}~dev.json` | Branch versions |
| `GET /composer/dists/{vendor}/{package}/{version}/{ref}.{type}` | Archive |
| `GET\|POST /composer/api/security-advisories/` | `composer audit` |
| `PUT /composer/packages/upload/{vendor}/{package}/{version}` | Upload a zip |

### Repository root

NORA's own: `metadata-url` and `security-advisories.api-url` on NORA's public
URL. With no upstream configured it also lists `available-packages` (the hosted
names), so Composer asks for no other package.

### Upstream root discovery

An upstream's `packages.json` says where its documents are (`metadata-url`, which
Composer resolves against the upstream's origin when it starts with `/`, and
`security-advisories.api-url`). NORA reads it as Composer does, caches it for
`metadata_ttl`, and falls back to `{upstream}/p2/%package%.json` when it cannot be
read. Private Packagist (`/org/p2/…`), Satis and Packagist mirrors work unchanged.

### Metadata (proxy)

- Cached **as the upstream sent it** at `composer/p2/{name}[~dev].json`, with the
  validators (`.meta`) and the upstream that served it (`.origin`).
- Fresh within `metadata_ttl`; then revalidated with `If-None-Match` /
  `If-Modified-Since` (Packagist sends both); a 304 restarts the TTL.
- Served stale (`x-nora-stale: true`) when every upstream that did not answer
  "not found" failed; a 404 from every upstream is a 404.
- Rewritten on the way out: every `dist.url` points at NORA, `dist.mirrors` is
  dropped, and only the requested package is served. The minified
  (`composer/2.0`) form is expanded, rewritten and minified again, so a version
  that inherits its `dist` from the one before still gets a URL naming its own
  version — curation reads the version from that URL.
- `Last-Modified` is the upstream's; a client `If-Modified-Since` naming it is a 304.
- A copy whose `.origin` is no longer a configured upstream is not trusted.

### Archives

A NORA archive URL names `{version}/{ref}.{type}`: the version as written (or `~`
and a digest of it when it holds characters a path or object key should not:
`dev-feature/x`), the `dist.reference` (or a digest of the upstream URL), and the
`dist.type`. A download:

1. Looks the version up in the cached upstream metadata — a release in
   `{name}.json`, a branch in `~dev.json` — and takes the upstream URL from there.
   A cached document past its TTL that does not list it is fetched once more; a
   fresh one is believed. **Anything the metadata does not list is a 404 and no
   upstream is asked**, so `/composer/dists/` is not an open proxy.
2. Curation: name + version, release date from the version's `time` (trusted
   upstream dates) or the metadata's cache time.
3. Cache hit: pin and `.sha256` sidecar checked, integrity pins, digest
   quarantine, Range/206.
4. Miss: fetched with redirects followed one hop at a time (at most 10, one
   `proxy_timeout` for the chain); credentials go only while the chain stays on
   the origin of the URL asked. `dist.shasum` (sha1) is checked when the upstream
   gives one (Packagist leaves it empty for GitHub archives).

**Credentials for archives.** The upstream's own credential on its own origin (a
private repository serving its archives); `github_token` as a Bearer on
`https://api.github.com` only. Packagist's archives are
`api.github.com/repos/{owner}/{repo}/zipball/{ref}`, which redirects to
`codeload.github.com` — which gets no token — and rate-limits an anonymous client
to 60 requests an hour.

### `source` and VCS fallback

Composer clones a version's `source` when its dist download fails — a refusal by
curation included — and reaches the VCS host without NORA. `keep_source = false`
lists every version NORA serves an archive of without its `source`; a version with
no dist keeps it (it has no other way to install). The default keeps Composer's and
Nexus's behaviour; with curation enforced, `false` is recommended.

### Hosted

Composer has no publish command; the upload follows the Nexus Composer API shape:
`PUT /composer/packages/upload/{vendor}/{package}/{version}` with the zip as body.

- `composer.json` is read from the archive where Composer reads it
  (`Composer\Util\Zip::locateFile`): the top level, or the single top-level
  directory (`__MACOSX` ignored). A minimal zip reader: end-of-central-directory,
  central directory, one local header, stored or deflate; every offset and length
  checked; `composer.json` capped at 1 MiB (deflate bombs stop at the cap);
  zip64 and encrypted members refused.
- Its `name` must be the path's; its `version`, if set, must normalize to the
  path's. Versions are normalized as Composer's `VersionParser::normalize` does
  (`v1.0` = `1.0.0.0`) and are immutable (409). Branch versions are refused.
- Storage: `composer/hosted/{name}/versions/{normal}.json` (composer.json + `name`,
  `version`, `time`, `dist {type, reference, shasum}` — sha1 of the zip),
  `.../dists/{normal}.zip` (+ `.sha256`), and `.../p2.json`, regenerated by
  listing the version documents under the package's publish lock (no shared
  read-modify-write, as npm since #39). A 201 is answered only once the
  regenerated document lists the version. A missing `p2.json` is rebuilt on read.
- **A package with any uploaded version is served from those alone**: its p2
  document is NORA's, its `~dev` document is empty, and no upstream is asked for
  it (dependency confusion). OIDC `namespace_scope` is enforced on `vendor/package`.

### Security advisories

`composer audit` posts `packages[]=…` to the root's `api-url`. NORA strips every
hosted or internal name, answers `{"advisories":{}}` itself when none is left,
and forwards the rest to the first upstream whose root names an advisories API.
Treated as a read under `anonymous_read`, like `npm audit`. `composer update`'s
`block-insecure` check reads the advisories inline in the p2 documents
(`security-advisories.metadata: true`), which NORA serves as cached.

### Curation and namespace isolation

Names compare in lowercase (`curation_name`), versions in Composer's normal form
(`curation_version`). An internal name (`curation.internal_namespaces`, e.g.
`acme/*`) is never asked of an upstream: p2, `~dev`, archive and advisories alike.
Metadata requests are checked by name; downloads by name, version and date.

## Client Configuration

```json
{
  "repositories": [
    { "type": "composer", "url": "https://nora.example/composer" },
    { "packagist.org": false }
  ]
}
```

```bash
composer config --global http-basic.nora.example ci-bot nra_xxx
curl -u ci-bot:nra_xxx -X PUT --data-binary @acme-greeter-1.0.0.zip \
  https://nora.example/composer/packages/upload/acme/greeter/1.0.0
```

## Verified against

The real `composer` 2 client (Docker `composer:2`) and repo.packagist.org:
`install` of monolog/monolog and symfony/console through NORA with packagist.org
disabled; `audit` forwarding; an uploaded package installed beside proxied ones
(Composer's own sha1 check on the hosted dist).

## Out of Scope (v1)

- Composer 1 / `providers`, `search` and `list` endpoints
- Uploading branch versions; deleting versions
- `nora mirror composer`, `nora import` of Composer repositories, retention
- VCS (git) repositories as sources; dist mirrors
